# Round 9–10 — เตรียมขึ้นเซิร์ฟเวอร์จริง: เซิร์ฟเวอร์เป็นเจ้าของตัวละคร · ตลาดผู้เล่น · ระบบเศรษฐกิจ

เอกสารนี้สรุปสิ่งที่เปลี่ยนเพื่อให้เกมพร้อมขึ้นเซิร์ฟเวอร์จริง วิธีติดตั้ง และสิ่งที่ยังต้องทำต่อ
ตัวเลขทุกตัวมาจากโค้ดและผลทดสอบจริงในรอบนี้

**ไม่ได้แตะ (รอปรับเข้า):** ข้อมูล NPC · หน้าตาตัวละคร 5 อาชีพ · เอฟเฟกต์สกิล · ไอคอนสกิล (ดูข้อ 6 เรื่องจุดเสียบ)

## 1. ปัญหาเดิม และสิ่งที่แก้

| Offline Vault ใช้ชื่อโซนเก่า และจ่ายเข้าคลังเก่า | ปิดไว้ก่อน (ตอบ 410) และเอาปุ่มออก |

## 2. เซิร์ฟเวอร์เป็นเจ้าของตัวละคร (Round 9)

**หลักการ: กติกาชุดเดียวกันทั้งสองฝั่ง**
- การเปลี่ยนเงิน ไอเทม เควส และสกิลทุกอย่างย้ายไปเป็นฟังก์ชันล้วน ไม่มี side effect ใน `src/game/economy/core.ts`
- เบราว์เซอร์และเซิร์ฟเวอร์รันโค้ดเดียวกัน
- เทสต์ parity ยืนยันว่า store แบบใหม่ให้ผลเหมือนแบบเดิมทุกฟิลด์ เมื่อใช้ random seed เดียวกัน

**ออนไลน์ทำงานอย่างไร**

| ข้อความ | หน้าที่ |
|---|---|
| `CHAR` | ล็อกอินแล้วเซิร์ฟเวอร์ส่งตัวละครมาให้ (ของ Guest ในเครื่องไม่ถูกนำเข้า) |
| `ACT` | ทุกการกระทำทางเศรษฐกิจ เช่น ซื้อ ขาย สวม ตีบวก คราฟ เควส สกิล เดินทาง |
| `STATE` | เซิร์ฟเวอร์ส่งเฉพาะส่วนที่เปลี่ยนกลับมา |

- การกระทำที่ผลแน่นอน (ซื้อของ สวมใส่) แสดงผลทันทีในเครื่อง แล้วเซิร์ฟเวอร์ยืนยันด้วยผลเดียวกัน
- การกระทำที่ต้องสุ่ม (ตีบวก คราฟ กล่องเริ่มต้น รางวัลฆ่า และตลาดทั้งหมด) รอผลจากเซิร์ฟเวอร์อย่างเดียว ลูกเต๋าอยู่ที่เซิร์ฟเวอร์

**การต่อสู้**

เบราว์เซอร์ยังจำลองการต่อสู้เอง (ลื่นไหล ไม่หน่วง) แต่การได้รางวัลจากการฆ่าต้องผ่านเซิร์ฟเวอร์ (`KILL`) ซึ่งตรวจว่า:
1. มอนตัวนั้นมีอยู่จริงบนแผนที่ที่ตัวละครอยู่
2. เกิดใหม่แล้ว (ตัวธรรมดา 8 วินาที บอส 5 นาที)
3. อยู่ในระยะ 40 m จากจุดเกิด
4. ตัวละครมีพลังพอฆ่าได้จริง ด้วยถังดาเมจ (damage budget):
   - ถังเติมด้วย DPS สูงสุดที่ตัวละครทำได้ ซึ่งคำนวณจากคลังสกิลจริง
   - จุได้ 10 วินาทีของ DPS นั้น หรือเท่า HP ของมอนที่อึดที่สุดบนแผนที่ แล้วแต่อันไหนมากกว่า
   - Round 10 เพิ่มเงื่อนไขหลังนี้ เพื่อให้ผู้เล่นที่อ่อนกว่าแต่เล่นจริง ใช้เวลาตีบอสนานก็ยังได้รางวัล

**การเดิน (`POS`)**
- ตำแหน่งต้องเดินได้จริงบนแผนที่ และไม่เร็วกว่าความเร็วตัวละคร × 1.35 (มีโควตาพุ่งตัว 14 m)
- ถ้าผิด เซิร์ฟเวอร์ดึงกลับ (`POS_FIX`)

**การบันทึก**
- บันทึกลง `characters` ราว 2 วินาทีหลังการเปลี่ยนแปลง และทันทีเมื่อออกจากเกมหรือรีสตาร์ต
- ทุกครั้งตรวจเลข revision ถ้ามีโปรเซสอื่นเขียนตัวละครเดียวกัน จะปฏิเสธและตัดการเชื่อมต่อแทนการเขียนทับ

**นำเข้าเซฟเก่าครั้งเดียว** (`importSave.ts`)
- ทำตอนตัวละครออนไลน์ครั้งแรก
- ไม่เชื่อค่าใดในเซฟเก่า: ไอเทมสร้างใหม่จากแคตตาล็อก, ตีบวกเกิน +6 ถูกตัด, เงินเกิน 50,000 ถูกตัด, สกิลต้องพอดีกับแต้ม
- ตั้ง `IMPORT_MODE=fresh` เพื่อเริ่มใหม่หมด

**เล่นออฟไลน์ / Guest:** เหมือนเดิมทุกอย่าง บันทึกในเครื่อง

## 3. ตลาดผู้เล่นและจดหมาย (Round 10)

ตลาดอยู่ที่ **Silas Vane** (นายหน้าตลาด) ในทุกเมืองหลวง

ข้อควรรู้ก่อน:
- เปิดดูตลาดได้ทุกที่ แต่ลงขาย ซื้อ และถอน ต้องยืนใกล้ Silas
- จดหมายเปิดรับได้ทุกที่

### กติกา
หลักคิดมาจาก Lumivara แต่ปรับเป็นของเราเอง ไม่ได้ลอกตัวเลข

| กติกา | ค่าเริ่มต้น | เหตุผล |
|---|---|---|
| ค่าลงขาย | 2% (ขั้นต่ำ 10 SG) จ่ายทันที **ไม่คืนแม้ยกเลิก** และถูกเผาทิ้ง | กันลงขายเล่น ๆ และเป็นตัวดูดเงิน |
| ภาษีการขาย | เริ่ม 6% ปรับอัตโนมัติในช่วง 4–12% ถูกเผาทิ้ง | ตัวดูดเงินหลัก และใช้คุมเงินเฟ้อ |
| ราคาขั้นต่ำ | ตามระดับ × (1 + 15% ต่อขั้นตีบวก) และไม่ต่ำกว่าครึ่งของราคาขายกลาง 7 วัน | กันทุ่มราคาและกันโอนมูลค่าระหว่างตัวละคร |
| ซื้อของตัวเองไม่ได้ | ตรวจทั้งในเกมและในฐานข้อมูล | กันปั่นราคา |
| ลงขายพร้อมกัน | สูงสุด 20 รายการ | — |
| ยกเลิก | ไม่เกิน 6 ครั้งต่อชั่วโมง | กันสแปม |
| อายุประกาศ | 72 ชม. แล้วของกลับทางจดหมาย | — |
| ของที่สวมอยู่ | ต้องถอดก่อน | — |
| ไอเทมเดียวกัน | อยู่ในตลาดได้ครั้งเดียว | ฐานข้อมูลบังคับด้วย unique index |

### ไม่มีของซ้ำ ไม่มีของหาย
ทุกการทำรายการเกิดในทรานแซกชันเดียวกับการเขียนตัวละคร และต้องตรงกับเลข revision ของตัวละคร:

| ทำรายการ | สิ่งที่เกิดพร้อมกันในทรานแซกชันเดียว |
|---|---|
| ลงขาย | ไอเทมออกจากกระเป๋า + สร้างประกาศ + หักค่าลงขาย |
| ซื้อ | หักเงินผู้ซื้อ + ไอเทมเข้ากระเป๋าผู้ซื้อ + ปิดประกาศ + ส่งเงินให้ผู้ขายทางจดหมาย (ราคา − ภาษี) |
| ถอน | ปิดประกาศ + ไอเทมกลับกระเป๋า |
| รับจดหมาย | ทำเครื่องหมายว่ารับแล้ว + เงินและไอเทมเข้าตัว |

ถ้ากระเป๋าเต็ม ของรอในจดหมายต่อ และทุกรายการที่มีเงินเข้าออกถูกบันทึกใน `economy_ledger`

ผู้ขายที่ออนไลน์อยู่จะได้รับแจ้ง 📬 ทันทีเมื่อขายได้ หรือเมื่อของหมดเวลาและถูกส่งคืน

### หน้าต่างในเกม (`Marketplace.tsx`)
- แท็บ: ตลาด (ค้นหา, กรองระดับ, แบ่งหน้า) · ลงขาย · รายการของฉัน · จดหมาย
- ก่อนยืนยัน แสดงค่าลงขาย ภาษีตอนนี้ และเงินที่จะได้รับ
- ถ้าเล่นออฟไลน์ แจ้งว่าต้องเชื่อมต่อเซิร์ฟเวอร์ก่อน

## 4. ควบคุมเงินเฟ้อ และตัวเลขเศรษฐกิจ

**การคุมเงินเฟ้ออัตโนมัติ** (`nextTax` ใน `balance/market.ts`)

ทุกวันตามเวลาไทย เซิร์ฟเวอร์:
1. บันทึก SoulGod หมุนเวียน (ในตัวละครทั้งหมด + เงินที่รอในจดหมาย) ลงตาราง `economy_daily`
2. เทียบกับ 7 วันก่อน
3. ถ้าโตเร็วกว่าเป้า 1% ต่อสัปดาห์ ขึ้นภาษี ถ้าหดตัว ลดภาษี (ปรับได้ไม่เกิน 0.5% ต่อวัน อยู่ในช่วง 4–12%)

- ต้องมีข้อมูลอย่างน้อย 3 วันก่อนจะเริ่มปรับ
- รีสตาร์ตเซิร์ฟเวอร์กลางวันจะไม่ปรับซ้ำ (เก็บวันที่ปรับล่าสุดใน `economy_state`)

**หน้าแอดมิน → ภาพรวม:** ตัวละครบนเซิร์ฟเวอร์ · SoulGod หมุนเวียน · เงินที่ถูกเผา 7 วัน · ภาษีตอนนี้และอัตราการโต · ตารางรายวัน 14 วัน

**หน้าแอดมิน → ตลาด & เศรษฐกิจ:** เพิ่มค่าที่ตั้งได้ ได้แก่
- เปิด/ปิดการปรับภาษีอัตโนมัติ, ภาษีต่ำสุด/สูงสุด, เป้าการโตต่อสัปดาห์, ปรับได้สูงสุดต่อวัน
- จำนวนครั้งที่ยกเลิกได้ต่อชั่วโมง
- SoulGod บอสภาคสนามและบอสดันเจี้ยน 1–3

> ⚠️ ถ้าแอดมินเคยบันทึกค่าตลาดไว้ในฐานข้อมูลแล้ว (เช่น ภาษี 5%) ค่าที่บันทึกไว้จะชนะค่าเริ่มต้นใหม่ ให้ตรวจในแท็บตลาดหลังอัปเดต

**สิ่งที่ตรวจแล้วว่าดีอยู่แล้ว ไม่ต้องแก้**
- ราคารับซื้อของ NPC ต่ำอยู่แล้ว (อุปกรณ์ 1–24 SG, ถ้วยรางวัลบอส 1,000–10,000) ตรงหลักว่าของดีต้องไปขายในตลาด
- ร้าน NPC ไม่ขายอุปกรณ์ระดับสูง

## 6. จุดเสียบสำหรับส่วนที่กำลังปรับ (ไม่ได้แก้ในรอบนี้)

**ข้อมูล NPC** — `src/game/npcs.ts`, ตำแหน่งจาก `capitalPlan.ts` (`doorSpot`)
- เซิร์ฟเวอร์อ้าง NPC ด้วยรหัสบริการ (`service`) เท่านั้น: `shop`, `enhance`, `starter`, `blessing`, `market`, `skills`, `travel`
- เปลี่ยนชื่อ บทพูด หน้าตา ได้อิสระ ขอแค่คงรหัส `service` เดิม และตำแหน่งยังมาจาก `doorSpot`

**หน้าตาตัวละคร 5 อาชีพ**
- เซิร์ฟเวอร์เก็บแค่ `classId` และ `gender` ส่วนภาพและสไปรต์อยู่ฝั่งเบราว์เซอร์ทั้งหมด
- ชุดแฟชั่นเป็นไอเทมช่อง `costume` ซื้อขายในตลาดได้

**เอฟเฟกต์และไอคอนสกิล**
- อยู่ในคลังสกิล (`skills/defaults.ts` + Skill Forge) ซึ่งเป็นเรื่องภาพล้วน
- ถ้าเปลี่ยนตัวคูณดาเมจ คูลดาวน์ หรือ AoE เพดานฆ่าบนเซิร์ฟเวอร์ (`legitDps`) คำนวณตามให้เอง
- ต้องรันเทสต์ `tests/realm-dps.test.ts` ซ้ำ เพื่อยืนยันว่าผู้เล่นจริงไม่ถูกปฏิเสธ

## 7. ขั้นตอนขึ้นเซิร์ฟเวอร์จริง

**1. Supabase:** รัน migration ตามลำดับถึง `202610250009_characters.sql` และ `202610250010_realm_market.sql` (รันซ้ำได้ปลอดภัย)

**2. Realm (Railway service แยก)**
- Root Directory = `/` · Dockerfile = `apps/game-server/Dockerfile`
- ตัวแปรที่ต้องตั้ง:
  - `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY`
  - `ALLOWED_ORIGIN` (โดเมนเว็บ)
  - `CLOSED_BETA=true`, `MAX_PLAYERS`
- ตัวแปรที่ตั้งหรือไม่ก็ได้:
  - `IMPORT_MODE` (`sanitize` / `fresh`), `IMPORT_GOLD_CAP` (50000)
  - `SAVE_DELAY_MS` (2000), `BOSS_PURSE_MAX` (3000000)
  - `KILL_DPS_SLACK`, `KILL_BURST_SECONDS`
- **ห้ามตั้ง `REALM_MEMORY=1` บนเซิร์ฟเวอร์จริง** (โหมดนี้สำหรับทดสอบเท่านั้น และรับ token แบบ dev)
- ใช้ `numReplicas: 1` ทั้งหมดอยู่ในห้องเดียว ถ้าจะขยายต้องแบ่งตาม channel

**3. เว็บ:** ตั้ง `NEXT_PUBLIC_GAME_SERVER_URL=wss://<realm>` ตอน build

**4. ในเครื่องก่อน deploy**
- `npm install && npm run build && npm test` ที่ root
- `npm install && npm test` ใน `apps/game-server`: สร้าง package-lock ให้ build ซ้ำได้เหมือนเดิม และรันเทสต์ realm

## 9. สิ่งที่ยังเหลือ (ตามความจริง)

1. **การต่อสู้ยังจำลองในเบราว์เซอร์**
   - เซิร์ฟเวอร์ตรวจการฆ่าด้วยกติกาข้อ 2 แล้ว แต่ไคลเอนต์ที่ถูกแก้ยังฟาร์มได้เร็วเท่า "ผู้เล่นที่เก่งที่สุดที่เป็นไปได้" ได้
   - ระดับนี้เทียบเท่าบอท AUTO ที่เกมอนุญาตอยู่แล้ว
   - ถ้าต้องการกันสนิท ต้องย้ายมอนในทุ่งไปจำลองบนเซิร์ฟเวอร์ ซึ่งเป็นงานใหญ่รอบถัดไป
2. **ปาร์ตี้ในทุ่งยังเป็นภาพ**
   - แต่ละคนจำลองมอนของตัวเอง บอสดันเจี้ยนจึงยังไม่ใช่การตีร่วมกันจริง
   - มีแค่ Titan ที่เป็นบอสร่วมบนเซิร์ฟเวอร์
3. **เงินพรีเมียมและร้านเติมเงิน** — รอการตัดสินใจและเรื่องกฎหมาย
4. **ยังไม่ได้ทดสอบกับ Supabase และ Railway จริง, ยังไม่มี load test 500 คน, ยังไม่ได้รัน `next build` ในเครื่องนี้**
   - เครื่องนี้ต่อ npm registry ไม่ได้ จึงสร้าง package-lock ของ realm ไม่ได้ ต้องรันในเครื่องคุณ
5. **ตารางเก่าไม่ได้ใช้แล้ว แต่ยังไม่ลบ** (`inventory_items`, `player_wallets`, `market_listings`, `offline_vault_jobs`)
   - ลบได้หลังยืนยันว่าไม่มีข้อมูลที่ต้องเก็บ
6. **Offline Vault ปิดอยู่** — ถ้าจะเปิดใหม่ ต้องสร้างบน realm พร้อมเพดานรายวัน
