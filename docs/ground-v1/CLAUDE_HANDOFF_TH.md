# ส่งต่อ Claude: พื้นเกม Round 23

## ข้อสรุปจากการตรวจ overview เดิม

ภาพใน maps-v2 มีขนาด 1536 × 1024 แต่เป็นภาพ isometric/oblique มีกรอบดำและวัตถุสูงติดอยู่ในภาพ ขนาดภาพไม่ใช่ปัญหาเดียว: ถ้าวางลง plane แล้วใช้กล้องเอียงอีกครั้ง จะบิดมุมซ้ำ อาคารกลายเป็นภาพแบน และถนน/น้ำในภาพไม่ตรง collider ของเกม การ crop, resize หรือ upscale ไม่แก้ความผิดพลาดนี้

ใช้ภาพเดิมเป็น concept art, หน้าจอเลือกแผนที่ หรือแผนที่ย่อแบบภาพประกอบได้ ถ้าจะใช้เป็นฉาก 2.5D กล้องล็อก ต้องสร้างการแปลงพิกัดและ collision ใหม่ตามภาพ และต้องแยกวัตถุที่บังตัวละคร ไม่ใช่ drop-in สำหรับเกม 3D ปัจจุบัน

## ไฟล์ชุดนี้

สร้างใหม่ด้วยการ bake พื้นจากข้อมูลเกมและวัสดุเดิมอย่างกำหนดพิกัดได้แน่นอน ไม่ใช่การยืดภาพ overview และไม่ใช่ภาพวาด AI ใหม่

- 13 แผนที่ ทุกแห่ง 240 × 240 เมตร
- ground-basecolor-4096.png: master lossless RGB 4096 × 4096 มองตรงจากด้านบน ไม่มีตัวอักษร อาคาร ต้นไม้ เสาวาร์ป หรือเงาวัตถุ
- ground-basecolor-4096.webp: รุ่นบีบอัดสำหรับเว็บ คุณภาพ 94; สีอาจต่าง PNG เล็กน้อยจาก compression
- ground-r0-c0-2048.png ฯลฯ: 4 ชิ้น lossless ประกอบกลับได้ตรงกับ master ทุกพิกเซล; ใช้เฉพาะกรณีต้องแบ่ง mesh/streaming ไม่ใช่ว่า 4 ชิ้นกิน VRAM น้อยกว่าไฟล์เดียวเมื่อโหลดทั้งหมด
- materials/: tile เดิม 1024 × 1024 สำหรับ detail ระยะใกล้ ปูซ้ำทุก 8 เมตร
- surface-mask.png: 480 × 480 RGBA; R=ถนน G=ลาน B=น้ำ/เหว A=255; นี่คือชนิดพื้น ไม่รวมต้นไม้และหิน
- walkable-mask.png: 480 × 480 ขาว=ศูนย์กลางตัวละครเดินได้ ดำ=บล็อก รวมตัวชนพร็อพแล้ว ห้ามใช้แทนสีพื้น
- runtime-map.json: navigation, gates, colliders, scenery, spawns และผังต้นทาง จากเกมรอบล่าสุด
- alignment-debug.svg: แสดงวงฟ้าตรงวาร์ปและจุดทองตรงมอนสเตอร์ ใช้ตรวจเท่านั้น ห้ามใช้เป็นพื้นเกม
- warp-gate.png: sprite เสาวาร์ป ต้องวางแยกตาม runtime-map.json
- manifest.json: ขนาด พิกัด และตำแหน่งของทุก tile

## พิกัดและ UV — ห้ามกลับแกน

มุมซ้ายบนของไฟล์คือ (x=-120, z=-120) คอลัมน์เพิ่มไปทาง +x แถวเพิ่มไปทาง +z

สำหรับภาพขนาด W × H ตำแหน่งศูนย์กลางพิกเซล:

    x = -120 + (column + 0.5) * 240 / W
    z = -120 + (row + 0.5) * 240 / H

Three.js PlaneGeometry(240,240) หมุน x=-PI/2 และ TextureLoader ค่า flipY=true:

    u = (x + 120) / 240
    v = (120 - z) / 240

ถ้าใช้ shader ที่อ่าน world.xz โดยตรง ให้ใช้สูตร UV ข้างบน ห้ามนำ (z+120)/240 มาใช้โดยไม่ชดเชย flipY ตรวจ orientation ด้วย gates ใน alignment-debug.svg เทียบกับ runtime-map.json โดยเฉพาะประตูของ wild0 และ wild1 ซึ่งอยู่คนละด้าน

แยก mask เป็น Linear data/NoColorSpace ใช้ NearestFilter ไม่มี mipmap สำหรับตรรกะ collision; ground basecolor ใช้ SRGBColorSpace, mipmaps, linear filtering, anisotropy ตามค่าที่อุปกรณ์รองรับ

## แนวทางติดตั้งใน SoulForge

1. คัดลอกโฟลเดอร์แผนที่ไป public/art/ground-v1/<id>/ และ materials ไป public/art/ground-v1/materials/
2. ใช้ geometry ของ FarmGround.tsx เดิมที่เว้นหลุมน้ำ/เหวไว้ เพิ่ม UV จากตำแหน่ง vertex ด้วยสูตรด้านบน แล้วใช้ ground-basecolor-4096.webp เป็น map ของ MeshStandardMaterial หรือ MeshBasicMaterial ตามแสงที่ต้องการ
3. ยังคง plane น้ำ/เหวด้านล่างและ collision เดิมไว้ ภาพสีมืดใน basecolor ไม่ได้บล็อกการเดินด้วยตัวเอง
4. คง FarmScenery, NatureLayer และ Waygates แยกจากพื้น ห้ามวาดภาพ overview เดิมทับ แล้ววางต้นไม้/อาคารซ้ำอีกชั้น
5. ตัวอย่าง renderer ใน BakedFarmGround.example.tsx เป็นเอกสารส่งต่อ ไม่มีการเปลี่ยน renderer ปัจจุบันอัตโนมัติ ต้องทดสอบในโครงการก่อนเปลี่ยนจริง
6. ถ้าซูมใกล้ ให้ใช้วัสดุ tile 1024 กับ surface-mask ผสมรายละเอียดซ้ำทุก 8 เมตร (ระบบ FarmGround เดิมทำส่วนนี้แล้ว) หรือใช้พื้น bake เฉพาะระยะไกล อย่าขยาย texture ใหญ่เพื่อแก้ความเบลอทุกระยะ
7. จุดเกิด NPC/มอนสเตอร์ วาร์ป และ collider ใช้ JSON หรือโมดูลเกมเป็น source of truth อย่าสุ่มใหม่จากสีภาพ
8. โหลด texture เฉพาะแผนที่ปัจจุบัน และ dispose/unload เมื่อไม่ใช้ อย่า preload 13 ภาพ 4K พร้อมกัน

## ความละเอียดและหน่วยความจำ

- overview 1536 × 1024 มีความละเอียดไม่สม่ำเสมอเมื่อคลี่เป็นพื้น 240 × 240 ม. และพื้นที่ภาพส่วนหนึ่งเสียให้กรอบดำ
- 4096/240 ≈ 17.07 texels ต่อเมตร (1 texel ≈ 5.86 ซม.) เหมาะเป็น base color ระดับพื้นที่ แต่ไม่ใช่รายละเอียดสำหรับกล้องใกล้มาก
- tile เดิม 1024 ปูทุก 8 ม. = 128 texels ต่อเมตร จึงควรเก็บไว้เสริมระยะใกล้
- texture RGBA8 4096² ประมาณ 64 MiB; พร้อม mipmaps ประมาณ 85.3 MiB ต่อภาพ (ประมาณการ ไม่ใช่ VRAM ที่วัดจริง)
- 8192² เป็น 4 เท่าของ 4096²: 256 MiB และประมาณ 341.3 MiB รวม mipmaps จึงไม่จำเป็นต้องเริ่มที่ 8K
- PNG/WebP ลดขนาดไฟล์ส่งผ่านเครือข่าย แต่ไม่ได้รับประกันลดหน่วยความจำหลังถอดรหัสบน GPU; GPU compression เช่น KTX2 เป็นขั้น optimization ภายหลัง

## ข้อจำกัดภาพและการตรวจรับ

นี่เป็นพื้นเชิงเทคนิคที่ใช้วัสดุเดิมและตรงกับระบบเดิน ไม่ได้มีรายละเอียดงานวาดสวยเท่า concept ที่มีอาคารและฉากครบ ความสวยส่วนใหญ่ต้องมาจาก props, แสง, decal และขอบน้ำ/เหวที่ Claude ทำต่อ โดยห้ามปิดทางล่า/วาร์ป

ก่อนรวมงาน ให้ตรวจ:
- ขนาด 240 ม., ถนน 10 ม., ลานกลาง 40 ม., ลานย่อยตาม JSON
- ประตูและภาพพื้นไม่กลับแกน; จุดเกิดไม่ชนวัตถุ
- หลุมน้ำ/เหวไม่ถูก floor mesh ปิด; ตัวละครเดินทะลุไม่ได้
- รอยต่อ tile ไม่มีช่องว่างและไม่ได้ใช้ RepeatWrapping กับภาพแผนที่ทั้งผืน
- ทดสอบภาพระยะใกล้/ไกลและหน่วยความจำบนอุปกรณ์เป้าหมายจริง
